# Сервер синхронизации СВАЛКИ

Небольшой сервер на [PocketBase](https://pocketbase.io): в Docker или обычной службой systemd. Хранит записи всех устройств аккаунта, рассылает изменения сразу (realtime) и делает ежедневные резервные копии. Бесплатно, без внешних сервисов.

## Установка

Если на сервере есть Docker, сервер ставится в контейнер. Без Docker (или с `--mode native`) он ставится обычной службой `svalka-sync` (нужны curl и unzip, памяти около 30 МБ). На сервере:

```bash
git clone https://github.com/cveloy102/reminder.git && cd reminder/server
sudo ./install.sh --domain sync.example.com --admin-email me@example.com
```

Скрипт ставит сервер в `/opt/svalka-sync`, слушает `127.0.0.1:8090` и в конце печатает пароль администратора (один раз).

HTTPS:
- если порты 80 и 443 свободны — добавь `--caddy`, сертификат Let's Encrypt получится сам;
- если 443 уже занят (nginx, VPN) — направь поддомен на `127.0.0.1:8090`, пример в `nginx-example.conf`;
- если на сервере уже есть свой Caddy — добавь в `/etc/caddy/Caddyfile` блок и выполни `systemctl reload caddy`:
  ```
  sync.example.com {
      reverse_proxy 127.0.0.1:8090
  }
  ```

Опции: `--mode docker|native`, `--port`, `--dir`, `--signup` (открыть самостоятельную регистрацию), `--public` (слушать все адреса, без прокси не нужно). Повторный запуск обновляет сервер и не трогает данные.

## Управление

```bash
cd /opt/svalka-sync
./svalka-sync.sh status
./svalka-sync.sh user add friend@example.com 'пароль'   # создать аккаунт
./svalka-sync.sh user passwd friend@example.com 'новый'
./svalka-sync.sh signup on|off                           # регистрация из приложения
./svalka-sync.sh backup user@backup-host:/backups/       # копия на другой сервер
```

Автоматические копии: каждый день в 03:00, хранятся последние 7 (`pb_data/backups`). Для копии на зарубежный сервер можно добавить в cron: `0 4 * * * /opt/svalka-sync/svalka-sync.sh backup user@host:/backups/`.

Панель администратора PocketBase: `https://<домен>/_/`.

## Как устроено

- `pb_migrations/` — коллекция `items`: одна строка на запись приложения, у каждой записи владелец. Правила доступа: пользователь видит и меняет только свои записи.
- `pb_hooks/` — закрытая регистрация (если не включена), защита от затирания новой правки старой (`409`), `GET /api/svalka/info` для проверки адреса из приложения.
- Приложения синхронизируются так: забирают изменения с сервера, объединяют (побеждает более свежая правка), отправляют свои; удаление «навсегда» передаётся всем устройствам.

Для интеграции с панелью: `install.sh` неинтерактивный, всё задаётся флагами, код выхода 0 — успех; `svalka-sync.sh` — команды для управления аккаунтами.
