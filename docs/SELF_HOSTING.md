# Свой сервер синхронизации: пошагово

С этой инструкцией сервер синхронизации СВАЛКИ ставится на свой VPS без какой-либо панели. После установки телефон и компьютер показывают одни и те же записи, а изменения приходят за пару секунд. Всё бесплатно: нужен только свой сервер, сторонних сервисов и привязки карт нет.

Сервер работает на [PocketBase](https://pocketbase.io), это одна программа примерно на 30 МБ памяти. Хватит самого маленького VPS с 1 ГБ памяти.

## Что понадобится

1. **VPS** на Ubuntu 22.04/24.04 или Debian 12, с доступом `root` по SSH.
2. **Домен или поддомен**, например `sync.example.com`, направленный на IP сервера: в DNS нужна запись `A` → IP VPS. Без домена не получится HTTPS, а приложения подключаются только по HTTPS.
   Своего домена нет? Подойдёт бесплатный поддомен, например на [duckdns.org](https://www.duckdns.org).
3. **Почта для аккаунта администратора.** Это просто логин, письма на неё не приходят.

Проверь, что домен уже указывает на сервер (на своём компьютере):

```bash
ping sync.example.com      # должен показать IP твоего VPS
```

## Шаг 1. Зайти на сервер

```bash
ssh root@IP_СЕРВЕРА
```

В Windows это можно сделать в «Терминале» или PowerShell, там команда та же.

## Шаг 2. Положить файлы сервера на VPS

Нужна папка `server/` из этого репозитория. Выбери любой способ.

**Способ А, через git** (если у тебя есть доступ к репозиторию):

```bash
apt update && apt install -y git curl unzip
git clone https://github.com/cveloy102/reminder.git
cd reminder/server
```

Репозиторий закрытый, поэтому git спросит логин и пароль. Вместо пароля введи [токен GitHub](https://github.com/settings/tokens) с правом чтения репозитория.

**Способ Б, скопировать с компьютера.** Скачай репозиторий архивом (Code → Download ZIP), распакуй и отправь на сервер только папку `server`:

```bash
scp -r ./server root@IP_СЕРВЕРА:/root/svalka-server
```

Затем на сервере:

```bash
apt update && apt install -y curl unzip
cd /root/svalka-server
chmod +x install.sh svalka-sync.sh
```

## Шаг 3. Установить

Выбери команду по тому, что уже стоит на сервере.

**На сервере ничего нет, порты 80 и 443 свободны** (самый простой случай):

```bash
sudo ./install.sh --mode native --caddy --domain sync.example.com --admin-email me@example.com
```

Скрипт сам поставит Caddy и получит бесплатный сертификат Let's Encrypt.

**На сервере уже есть свой Caddy:**

```bash
sudo ./install.sh --mode native --domain sync.example.com --admin-email me@example.com
```

Потом добавь в конец `/etc/caddy/Caddyfile` такой блок и перезагрузи Caddy:

```
sync.example.com {
    reverse_proxy 127.0.0.1:8090
}
```

```bash
systemctl reload caddy
```

> Если панель или другой установщик перезаписывает `Caddyfile` целиком, этот блок пропадёт. Тогда синхронизация перестанет открываться по домену. Проверь блок после таких установок.

**Порт 443 занят nginx** (или VPN на nginx): направь поддомен на `127.0.0.1:8090`. Готовый пример лежит в [`server/nginx-example.conf`](../server/nginx-example.conf).

**Есть Docker и хочется в контейнере:** замени `--mode native` на `--mode docker`, остальное так же.

В конце скрипт **один раз** напечатает пароль администратора. Сохрани его. Чтобы пароль точно не потерялся, команду установки можно запустить так: `... | tee /root/svalka-sync-install.log`, тогда весь вывод сохранится в файл.

Проверь, что сервер отвечает:

```bash
curl https://sync.example.com/api/svalka/info
```

В ответ должна прийти строка с `"svalka"`.

## Шаг 4. Создать аккаунт

Регистрация из приложений по умолчанию закрыта, поэтому чужие люди не смогут завести аккаунт на твоём сервере. Аккаунт создаётся на сервере:

```bash
cd /opt/svalka-sync
./svalka-sync.sh user add me@example.com 'надёжный-пароль'
```

Если удобнее, можно открыть регистрацию, зарегистрироваться из приложения и закрыть её обратно:

```bash
./svalka-sync.sh signup on    # открыть
./svalka-sync.sh signup off   # закрыть
```

## Шаг 5. Подключить приложения

- **Android:** вкладка «ДАННЫЕ» → «ПОДКЛЮЧИТЬ СЕРВЕР». Введи адрес `https://sync.example.com`, почту и пароль.
- **Windows:** кнопка «СИНХР» в верхней строке окна. Введи тот же адрес, почту и пароль.

При первом входе записи с устройства объединяются с теми, что уже есть в аккаунте. Ничего не пропадает: если одна запись менялась на двух устройствах, остаётся более свежая правка.

## Обслуживание

```bash
cd /opt/svalka-sync
./svalka-sync.sh status                               # работает ли сервер
./svalka-sync.sh user passwd me@example.com 'новый'   # сменить пароль
./svalka-sync.sh backup user@другой-сервер:/backups/  # копия на другой сервер
systemctl restart svalka-sync                         # перезапуск (режим native)
journalctl -u svalka-sync -n 50                       # последние строки журнала
```

- **Резервные копии** делаются сами каждый день в 03:00, хранятся последние 7, папка `/opt/svalka-sync/pb_data/backups`. Чтобы копия каждую ночь уходила на другой сервер, добавь в `crontab -e` строку:
  `0 4 * * * /opt/svalka-sync/svalka-sync.sh backup user@host:/backups/`
- **Восстановление из копии вручную** (если вернул папку `pb_data` из резервной копии): после запуска выполни `./svalka-sync.sh new-instance`. Приложения один раз сверят все записи с сервером и дольют то, что было сделано после этой копии.
- **Обновление:** возьми свежую папку `server/` (шаг 2) и запусти ту же команду установки ещё раз. Данные не трогаются.
- **Панель администратора PocketBase:** `https://sync.example.com/_/`. Вход по почте администратора и паролю из шага 3.

## Если что-то не работает

| Что видно | Что проверить |
|---|---|
| Приложение пишет «Нет связи с сервером» | `curl https://домен/api/svalka/info` с компьютера. Если не отвечает, проверь DNS-запись и что Caddy/nginx запущен. |
| Ошибка сертификата | Домен должен указывать на этот сервер, а порты 80 и 443 должны быть открыты в файрволе провайдера. |
| «Неверная почта или пароль» | Есть ли аккаунт: `./svalka-sync.sh user add ...` выдаст ошибку, если уже есть. Тогда смени пароль через `user passwd`. |
| «Регистрация на этом сервере закрыта» | Это нормально. Создай аккаунт командой из шага 4. |
| Всё работало, а потом домен перестал открываться | Возможно, `Caddyfile` перезаписали. Верни блок из шага 3. |

Подробнее о том, как устроен сервер: [`server/README.md`](../server/README.md).
